# 無障礙檢查 / Accessibility

目標是 WCAG 2.1 AA。這份文件列出這個 App 的無障礙設計決策、每次改 UI 要過的檢查清單，以及自動掃描的做法。

## 設計決策

| 情境 | 做法 |
|------|------|
| 加入主畫面後沒有瀏覽器返回鍵 | 子頁面都有 `PageHeader` 的返回箭頭（`aria-label="返回"`），沒有歷史紀錄時退回指定頁 |
| 時間軸甘特圖對螢幕閱讀器不友善 | 音樂祭詳情頁的「演出陣容」清單是同一份資料的文字版；時間軸方塊本身仍是可聚焦的 `button`，`aria-label` 含藝人、舞台、時間、狀態 |
| 已加入／未加入只靠顏色深淺 | 已加入的方塊多一個 ✓、清單列右側有勾選圓鈕、`aria-pressed` 表達狀態 |
| 進行中、時間衝突 | 「LIVE」文字標籤、⚠ 圖示＋ `title` 文字，不只靠紅色／琥珀色 |
| 活動狀態（進行中／N 天後／已結束） | `StatusChip` 一律有文字 |
| 切換日期 | `role="group"` + `aria-pressed`，不用沒有 tabpanel 的 `role="tab"` |
| 可捲動的時間軸 | 容器 `tabindex="0"` + `role="region"`，鍵盤方向鍵可捲動 |
| 動畫 | 團名跑馬燈尊重 `prefers-reduced-motion`，並可在設定關閉 |
| 顏色 | 全部走 MD3 token，亮暗各一組；狀態文字避免 Tailwind `*-600` 在淺底上不足 4.5:1 的組合，改用 `*-700` / `dark:*-300` |
| 觸控目標 | 底部導覽 64px、清單列 ≥ 44px、圓形加入鈕 32px 但整列可點 |
| 語言與標題 | `<html lang="zh-TW">`，每頁 `document.title` 隨路由更新；`AccordionSection` 標題是真正的 `h2` |

## 改 UI 前後的檢查清單

- [ ] 新的可點元素是 `button` / `a`，或有 `role` + `tabindex` + Enter／Space 處理
- [ ] icon-only 按鈕有 `aria-label`；裝飾用 icon 是 `aria-hidden`
- [ ] 任何「選中／狀態」除了顏色還有形狀、文字或圖示
- [ ] 文字對比：一般文字 ≥ 4.5:1，大字 ≥ 3:1（用 DevTools 的 contrast 檢查）
- [ ] 標題層級不跳級（h1 → h2 → h3）
- [ ] 表單欄位有標籤（`<label for>` 或 `aria-label`；`md-outlined-text-field` 用 `aria-label` 或 `label` 屬性）
- [ ] 用鍵盤 Tab 走一遍：焦點順序合理、看得到焦點框、modal 內焦點不會跑出去
- [ ] 手機字體放大到 200% 不會破版、不會有橫向捲動（時間軸與地圖的容器內捲動除外）
- [ ] 深色模式與紅綠色盲模擬下仍分得出狀態

## 自動掃描

用 Playwright + axe-core 對正式 build 掃一遍，並用 Chromium 的視覺缺陷模擬拍色盲截圖：

```bash
npm run build && npm run preview &     # http://localhost:4173
```

```js
// a11y.mjs（範例，可放在 repo 外）
import { chromium, devices } from 'playwright';
import { readFileSync } from 'node:fs';
const axe = readFileSync('node_modules/axe-core/axe.min.js', 'utf-8');
const browser = await chromium.launch();
const ctx = await browser.newContext({ ...devices['iPhone 13'], locale: 'zh-TW' });
const page = await ctx.newPage();
for (const path of ['/', '/festival/<id>', '/festival/<id>/timeline', '/plan', '/settings', '/editor']) {
  await page.goto('http://localhost:4173' + path, { waitUntil: 'networkidle' });
  await page.addScriptTag({ content: axe });
  const { violations } = await page.evaluate(() =>
    axe.run(document, { runOnly: { type: 'tag', values: ['wcag2a', 'wcag2aa', 'wcag21aa', 'best-practice'] } })
  );
  console.log(path, violations.map((v) => `${v.impact} ${v.id} x${v.nodes.length}`));
  // 色盲模擬截圖
  const cdp = await ctx.newCDPSession(page);
  for (const type of ['deuteranopia', 'protanopia', 'achromatopsia']) {
    await cdp.send('Emulation.setEmulatedVisionDeficiency', { type });
    await page.screenshot({ path: `a11y-${path.replace(/\W+/g, '_')}-${type}.png` });
  }
  await cdp.send('Emulation.setEmulatedVisionDeficiency', { type: 'none' });
}
await browser.close();
```

自動掃描抓得到的大約只有三成問題（缺標籤、對比、ARIA 用法）；鍵盤走一遍與螢幕閱讀器（iOS VoiceOver、Android TalkBack）實測仍然必要。

## 已知限制

- 時間軸甘特圖在螢幕閱讀器下只能逐個方塊聽，沒有表格式的行列導覽；詳情頁清單是主要的替代路徑。
- `@material/web` 元件（switch、dialog、text field）的無障礙行為由套件負責，我們只補 `aria-label`。
- 地圖是圖片，沒有文字替代的場地資訊；`alt` 只有活動名稱。
